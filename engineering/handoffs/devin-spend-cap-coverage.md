- **Analyze:** Firebase (8/min per UID per isolate); DB-bound paid session plus atomic Quick/Forensic reservation, saved report before credit finalization, failure release. Integration Quick free: three per UID. The integration `deep-unpaid` lane returns `UPGRADE_REQUIRED` before queueing; its input/execution/output cells describe the downstream full path, which this caller cannot reach. Trial Quick and Forensic: one each per verified normalized email, except an already-started Quick UID retains the remaining old allowance. Per-network 6/day, 15/month when Cloudflare supplies the network identifier; platform 25 free Quick/day, 10 free Forensic/day; both pause at 200 paid starts/day. Optional Turnstile is an additional gate, not billing. Trial non-owner paid analyze takes a 300/day platform unit; unreadable counters fail open for paid, not for free. The owner bypasses reservations and these counters, not authentication or the local rate limit.
- **Analyze sizing and calls:** Quick rejects analyzed text over 75,000 characters; trial free full rejects over 105,000. No corresponding application text ceiling for paid/owner full, and no streaming whole-body size check in analyze or its full alias. Quick/full use defaults 100s/180s, provider sub-deadlines and bounded section/verification retries. Four Quick sections cap output at 3,500/5,000/3,500/3,500; six full sections cap at 8,000/8,192/8,000/7,000/4,500/5,000; optional full verification caps at 4,000 per call. Every section gets the document again. Two section attempts and two verification attempts; Quick may retry transport once inside each section attempt, full sets no inner transport retries. The local rate limits count requests, not provider attempts.
- **Assessment:** Firebase, owned matter, active UID-bound Pro session, same Forensic credit pool as paid Deep Scan. Credit is reserved before generation, finalized after storing the result, released for applicable failures; stored reports can be reused without paying the provider again. Only the generation action spends (not list/read/source-management operations). The body is actually streamed and capped at 150,000 bytes; up to 20 sources, up to 75,000 chars per source and across the source set. Single Opus 5 call, 75s, zero retries, 6,000 output tokens. It does **not** call analyze's local or trial paid daily limiter on either ref.
- **OCR:** Firebase, 20/min per UID per isolate. Same hard default limits for everyone on I: 20 MiB, 200 physical PDF pages, 30 pages eligible for OCR. Trial free: 10 MiB, 30 physical pages, 30 OCR pages, and before first OCR needs verified email, remaining free analysis entitlement, one of three lifetime OCR reads and one of 30 platform reads/day. The OCR units are committed at admission; they are not report reservations and are not refunded on provider failure. No per-network OCR counter. Trial paid/owner uses the larger defaults and skips OCR counters entirely. Each image/selected page gets Gemini (default 2.5 Flash, override via config), typically at most two transport attempts, 8,192 max output tokens/attempt, 60s/page under a 120s extraction budget. Native TXT/DOCX/PDF extraction is not billed; a single PDF request may still cause 30 logical OCR calls. The header and base64 checks aren't a bounded JSON stream.
- **Audio:** Alias re-exports the same handler (one 10/min UID bucket). Integration needs Firebase only; trial additionally requires a verified paid session or the verified owner. No credit is consumed, no cross-isolate or trial counter. 10 MiB base64 (~7.5 MiB audio), MIME allowlist, no seconds/minutes limit or streaming JSON bound. Gemini (configured audio model, default `gemini-3.6-flash`), two attempts within 60s, 8,192 token cap.
- **Queue:** Production consumer and staging relay/executor use the same analysis path after a durable claim (240s lease with heartbeat). The job inherits the Pages producer's reservation; the trusted job branch does not authenticate Firebase or take another rate/cap unit. Worker success finalizes, terminal failure releases, and recovered reports avoid another inference. Forensic without a usable queue is fail-closed. Cloudflare config has five retries on each queue, and DLQ may requeue a job with durable `attempt_count < 6` rather than infer itself. Queue deliveries/claims are not a currency or token allowance. A failed run can still cost inference even if the customer credit is reused or refunded.
- **Operator paths:** Staging probe requires the staging hostname, exact Firebase test project, allowlisted UID, explicit probe switch and customer analyzer disabled. Its service binding calls the same handler and gates. Input is a fixed synthetic fixture (no freeform source data); it uses the same section limits and 98s/178s deadlines without reserving credits. The CLI requires a local provider key, uses a fixed 3-page synthetic fixture, makes one Sonnet and two Opus calls, caps output at 16,000/12,000/14,000 with one SDK retry each, and has no application ledger. Do not run it as a test.

## Ranked spend gaps

Ranking considers repeatability in a normal authorized path, cost per accepted unit and which ref is affected. It is not a traffic or billing forecast. All figures are USD and assume uncached calls; aborted/failed attempts can have incurred charges. There is **no monetary hard ceiling** on either ref. A syntactic token allowance is not actual billed usage; provider context ceilings, reasoning tokens, model overrides and other metered features may differ.

1. **Full/Deep via Queue — highest modeled cost per customer analysis.** Opus 5 at the repository's $5/M input and $25/M output (`api/services/analyzerModels.ts::MODEL_PRICING`). Six section caps total 40,692 plus up to 4,000 verification tokens; two attempts for each produce an output-only envelope of 89,384 × $25/M ≈ **$2.23 per execution**, plus repeated full source input (e.g. 14 × 26,250 illustrative tokens ≈ **$1.84**). The paid/owner source size is not bounded by the app. A failed delivery can trigger another execution under the same reservation, increasing total inference without taking another daily unit. Trial paid cap covers admissions only and fails open on store error; trial free full has its own size and admission caps. Owner full has neither credit nor daily protection (owner access required).
2. **Scanned PDF OCR — broadest repeatable unmetered client work, on both refs.** 30 × 2 × 8,192 = 491,520 configured output tokens across possible attempts. Using public [Gemini 2.5 Flash standard pricing](https://ai.google.dev/gemini-api/docs/pricing) ($0.30/M non-audio input and $2.50/M output), the output envelope is **$1.23/upload**, plus PDF/page tokens (~$0.018 per 60,000 input tokens). This is a conservative budgeting envelope, not a prediction that both attempts return full outputs. Integration only has the per-isolate bucket; trial protects free OCR, but paid/owner has no debit or global request cap. Single-image OCR has one logical call and follows the same admission policy.
3. **Quick — smaller per run, uneven total exposure.** Sonnet 5, repo $2/M input and $10/M output. Four sections cap an initial pass at 15,500 total output; two section attempts each with one possible transport retry give an output envelope **$0.62**. At 75,000 chars and illustrative four chars/token, repeated source input for 16 calls is about **$0.60**, not including instructions. Integration uses per-user credits plus isolated request limits, trial adds shared starts; owner still has no ledger. This ranks below OCR on repeatability and does not count Deep Scan verification a second time.
4. **Final Case Assessment — paid and reservation-controlled, missing shared admission rate.** Single Opus call at $25/M output × 6,000 = **$0.15** plus source input (75k chars at illustrative 4 chars/token → **$0.094** before overhead). Not an unlimited successful paid lane: the Forensic allowance and stored-result reuse matter. Neither branch includes it in analyze's request caps; failed generations can cost money even after a customer credit release.
5. **Transcription — lower output exposure but no duration or spend meter.** Two attempts × 8,192 output tokens = 16,384. As a comparator only, public Gemini 2.5 Flash prices give **$0.041** output at $2.50/M, plus audio input at $1/M (~$0.0038 for ten minutes per attempt at an illustrative 32 audio tokens/sec). The configured 3.6 Flash default is not priced in this repo; do not apply 2.5 prices to an actual invoice. No application duration bound; compressed audio bytes alone do not bound minutes tightly. Integration only requires Firebase; the trial adds plan eligibility but still no credit debit or daily counter. Default and override prices should be checked before using this for a release budget. OCR/audio can swap rankings under model or usage changes.

**Separate reachability class:** staging probe and CLI can have Deep-like cost (CLI output envelope $1.62 at repo model rates with all SDK retries), but run fixed fixtures and require staging allowlist or provider key. Do not treat them as customer abuse paths. If legacy Express is deliberately exposed, prioritize its two unauthenticated audio routes and OCR fan-out (up to 20 pages × 6 Gemini attempts for pages needing OCR) ahead of its paid-session-only tools; Gemini model-dependent default output and absent app wall-clock limits prevent a meaningful hard dollar bound. The Express routes do not warrant a production incident on code reachability alone.

## Reproduction

Install with `npm ci --ignore-scripts` on Node 22. Run `NODE_OPTIONS=--no-experimental-webstorage npx vitest run tests/devin/spend-cap-coverage.test.ts` on this integration-based branch. For trial, use a detached worktree at the recorded T SHA and copy **only** that test file into its existing `tests/devin/`; run the same command from that worktree. The test detects the trial module in the target tree, not a mocked implementation or a remote ref. The two snapshots have identical npm lockfiles, so the worktrees can share installed dependencies. Run `npx tsc --noEmit -p .` in the integration worktree. No live services, paid provider requests, migrations or deployment are needed.
